\begin{frame}[fragile]\frametitle{Too Much of Anything is Good for Nothing!}
What happens when a data set has too many features? Here are a few possible situations you might come across:
\begin{itemize}
\item  You find that most of the features are correlated.
\item  You lose patience and decide to run a model on whole data. This returns poor accuracy and you feel terrible.
\item  You become indecisive about what to do
\item  You start thinking of some strategic method to find a few important features
\end{itemize}

More features means high dimensionality.

\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Curse of Dimensionality: Why It's High}
\begin{itemize}
\item  Datasets are typically high dimensional
 \item Images of $20 \times 20$ bitmaps have 400 dimensions; megapixel images have far more.
 \item In text, all words are features, say, $10^6$.
\end{itemize}
\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Why the Curse Hurts}
\begin{itemize}
 \item Machine learning methods are statistical: they need enough data points in every region of the space.
 \item As the dimensionality grows, there are fewer observations per region: density drops.
 \item Actual/True content is in the very small subset of this high dimensional space.
 \item The denser the space, the better for the algorithm, so this sparsity works against it.
\end{itemize}
\end{frame}



%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Two Approaches to Dimensionality Reduction}
\begin{itemize}
\item  How do you identify the highly significant feature(s) out of 1000 or 2000?
\item Feature selection: Select only relevant features (based on domain, correlation, etc)
\item Feature Extraction: Compose new features based on combination of all existing ones.
\end{itemize}
\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{PCA Is Feature Extraction}
\begin{itemize}
\item Principal Component Analysis (PCA) is a feature extraction method.
\item Projects data from high-dimensional space into a lower-dimensional space
% \item Not necessarily interested in ``losing information''; rather eliminate some of the sparsity
\end{itemize}
\end{frame}

\item weight

\begin{frame}[fragile] \frametitle{Too Many Features?}
\begin{itemize}
\item length of torso
% \item pant inseam length
\item hat size
\item left hand ring size
\item right hand ring size
\end{itemize}
Technically we have $10$ features, though most of the variation
in the data set can be summarized by at most 2 or 3 features.

What can you do? Domain knowledge?
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Reduction in Dimensions} 
In decreasing order of variation, consider the following measurements
that can be derived from these $10$ features
\begin{itemize}
\item height: captures a large amount of the variation in the total
dataset. 
\item body mass index: should be
relatively uncorrelated with overall height, captures much of the
next largest variation in the data. 
\item ratio of torso length to total height: attempts
to capture the remaining variation based on how height is distributed
over a given individuals frame.
\end{itemize}

This dimension reduction was based on domain knowledge, but is there anything generic? Yes, PCA (Principal Component Analysis).

PCA builds only linear combinations of the features, so it would not produce BMI (a ratio) exactly, but it typically recovers a ``size'' axis and a ``shape'' axis without any domain knowledge.

\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Reducing Dimensions}
\begin{block}{Think About It}
1. Which of these is feature extraction rather than feature selection?
\begin{enumerate}
  \item[A.] Dropping the three features that correlate least with the target
  \item[B.] Replacing 10 body measurements by 3 new features, each a weighted mix of all 10
  \item[C.] Keeping only the features that have non-zero variance
  \item[D.] Removing the features that have missing values
\end{enumerate}
2. You add many more features to a fixed-size dataset. Why can accuracy get worse?
\begin{enumerate}
  \item[A.] More features always add information, so accuracy cannot get worse
  \item[B.] The data become sparse: few observations fall in any region of the feature space, so the model overfits
  \item[C.] The computer runs out of memory, which lowers accuracy
  \item[D.] Extra features automatically become correlated with the target
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Reducing Dimensions}
\begin{block}{Answer}
\textbf{1. Correct: B.} Extraction builds new features from combinations of the old ones. A, C and D all keep a subset of the original features, which is feature selection.

\textbf{2. Correct: B.} In high dimensions the same number of points spreads over a huge space, so the data become sparse and the model finds patterns that do not generalize. Extra features can add information (A), but not for free.
\end{block}
\end{frame}

\begin{frame}[fragile] \frametitle{The Core Idea}
\begin{itemize}
\item PCA looks at the data and tries to find a direction-line along which data is spread the most.
\item Once done, you look for another (perpendicular) dimension which has second most variation.
\item These directions are called Principal Components.
\item Transforming the data to the coordinate system formed by the Principal Components means a
few axes now capture most of the variation, and that's the dimension reduction.
\end{itemize}
\end{frame}

\begin{itemize}

variance in the data
\item Second is the next orthogonal (uncorrelated) direction of greatest variability. So first remove all the variability along the first
component, and then find the next direction of greatest variability
\item  And so on
\end{itemize}

\begin{frame}[fragile]\frametitle{Quick Check: Why Maximize Variance?}
\begin{block}{Think About It}
PCA picks the direction that captures the maximum variance in the data. Why is that the
right criterion for a good 1-D summary of 2-D data, rather than, say, minimizing the range
of the projected values?
\begin{enumerate}
  \item[A.] Maximizing variance is arbitrary; any direction summarizes the data equally well.
  \item[B.] Because the data's total spread is fixed, maximizing the variance captured along
  a direction automatically minimizes the variance lost in the perpendicular direction, so
  it's the line closest to every point, not just an arbitrarily spread-out one.
  \item[C.] Maximizing variance guarantees the projection preserves the original units of
  measurement.
  \item[D.] Maximizing variance is used only because it's computationally cheaper than any
  alternative.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Why Maximize Variance?}
\begin{block}{Answer}
\textbf{Correct: B.} For data centered on its mean, the total squared distance from every
point to the origin is fixed. That total splits into ``variance captured along the chosen
line'' plus ``variance lost perpendicular to it''. So maximizing the first term automatically
minimizes the second: the max-variance direction is also the one that best preserves the
original structure, exactly as the earlier ``blue Z is better'' example showed.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Steps} 
\begin{itemize}

\item Standardize the data.
\item Compute the covariance matrix.
\item Obtain the Eigenvectors and Eigenvalues from the covariance matrix or correlation matrix, or perform Singular Value Decomposition.
\item Sort eigenvalues in descending order and choose the $k$
 eigenvectors that correspond to the $k$ largest eigenvalues where $k$
 is the number of dimensions of the new feature subspace ($k \leq d$).
\item Construct the projection matrix $W$ from the selected $k$  eigenvectors.
\item Transform the original dataset $X$ via $W$ to obtain a $k$-dimensional feature subspace $X'$.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Standardization: Centering and Scaling}
\begin{itemize}
\item Centering: subtract the mean of each feature (always required)
\item Scaling: divide each feature by its standard deviation
\begin{itemize}
\item Needed when features have different units or ranges
\item All features then have the same scale: $z = \frac{\text{value} - \text{mean}}{\text{standard deviation}}$
\end{itemize}
\item Without scaling, the feature with the largest numeric range dominates the components
\item PCA on centered and scaled data is PCA on the correlation matrix
\item Subtracting the mean simplifies the variance and covariance formulas; their values do not change
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Covariance Matrix Computation}
\begin{itemize}
\item Purpose: see how each pair of features varies together
\item Highly correlated features carry redundant information
\item The covariance matrix is a $p \times p$ symmetric matrix ($p$ = number of features)
\begin{itemize}
\item Its entries are the covariances of all possible pairs of features
\end{itemize}
\item Example: for 3 features $x$, $y$, $z$ it is a $3 \times 3$ matrix:
\[
\begin{bmatrix}
\operatorname{Cov}(x,x) & \operatorname{Cov}(x,y) & \operatorname{Cov}(x,z) \\
\operatorname{Cov}(y,x) & \operatorname{Cov}(y,y) & \operatorname{Cov}(y,z) \\
\operatorname{Cov}(z,x) & \operatorname{Cov}(z,y) & \operatorname{Cov}(z,z)
\end{bmatrix}
\]
\item The diagonal holds the variances, since $\operatorname{Cov}(x,x) = \operatorname{Var}(x)$
\item The matrix is symmetric: $\operatorname{Cov}(x,y) = \operatorname{Cov}(y,x)$
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{What's an Eigenvalue/Eigenvector?}
\begin{itemize}
\item Example: we have 2-dimensional vectors $v_1, v_2, \ldots, v_n$
\item Apply a linear transformation $T$ (a $2 \times 2$ matrix) to them: we obtain new vectors $b_1, b_2,\ldots,b_n$
\item The $b_i$ differ from the $v_i$ in length and direction (remember the homogeneous transformation matrix?)
\item But some special vectors stay on the same line: $T$ only scales them (a negative scale factor reverses them)
\item Those vectors are called eigenvectors; the scale factor is called the eigenvalue: $Tv_i=\lambda v_i$
\item Thus, each eigenvector has a matching eigenvalue
\end{itemize}

{\tiny (Ref: PCA: Eigenvectors and Eigenvalues - Valentina Alto)}

\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Eigenvectors of the Covariance Matrix}
\begin{itemize}
\item Take the covariance matrix $C$ and collect its eigenvectors as the columns of a matrix $V$
\item Put the matching eigenvalues on the diagonal of a matrix $L$
\item Together: $CV = VL$, that is, $C v_i = \lambda_i v_i$: $C$ only stretches each eigenvector
\item $C$ is symmetric, so its eigenvalues are real and its eigenvectors can be chosen perpendicular
\end{itemize}

\[
\begin{bmatrix}
\operatorname{Var}(x) & \operatorname{Cov}(x,y) \\
\operatorname{Cov}(y,x) & \operatorname{Var}(y)
\end{bmatrix}
\begin{bmatrix} v_1 \\ v_2 \end{bmatrix}
= \lambda
\begin{bmatrix} v_1 \\ v_2 \end{bmatrix}
\]

\begin{block}{Intuition}
This is the mathematical heart of PCA: the eigenvectors of the covariance matrix are exactly
the principal component directions, and their eigenvalues tell you how much variance each
direction captures. Sorting eigenvectors by eigenvalue and keeping only the top few is
precisely what ``keeping the principal components'' means.
\end{block}

{\tiny (Ref: PCA: Eigenvectors and Eigenvalues - Valentina Alto)}

\end{frame}

\begin{frame}[fragile]\frametitle{Eigenvalue and Eigenvector: Definition}
 \begin{itemize}
\item Let $A$ be an $n \times n$ matrix.  A {\em non-zero} vector $\vec{x}\in \mathbb{R}^n$ is 
called an \underline{eigenvector} of $A$ if there exists some scalar $\lambda \in \mathbb{R}$ so that 
$A \vec{x}= \lambda \vec{x}$.  \\ 
\item If $\vec{x}$ is an eigenvector of $A$,
the corresponding value $\lambda$ is called an \underline{eigenvalue} of $A$, and we say that 
$\lambda$ is an eigenvalue of $A$ with eigenvector $\vec{x}$.  

\item 
While an eigenvector $\vec{x}$ must be non-zero (so that we are always 
excluding the trivial case $A \vec{0}=\vec{0}$), it is possible for the value
$\lambda$ to be zero. 
\item  If $\lambda$ is an eigenvalue for $A$, the eigenvectors for $A$ corresponding to $\lambda$ along with $\vec{0}$ form a subspace of $\mathbb{R}^n$.
\end{itemize}

\begin{frame}[fragile]\frametitle{Deriving the Characteristic Equation}
% \begin{definition}
 % Show that 7 is an eigenvalue for
 % \[
 % A = \left( \begin{array}{rrrrr} 2 & 4 \\ 5 & 3 \end{array} \right).
% \]
% \end{definition}


\begin{definition}
For any scalar $\lambda$,
\begin{eqnarray*}
 A \vec{x} &=& \lambda \vec{x}   \\
 &\Leftrightarrow&  
A \vec{x} -\lambda \vec{x} = \vec{0}  \\
 &\Leftrightarrow&  
 A \vec{x} -\lambda I \vec{x} = \vec{0}  \\
  &\Leftrightarrow& 
  \left( A - \lambda I \right) \vec{x} =\vec{0} \\
   &\Leftrightarrow&  
\vec{x} \in \operatorname{Nul}(A -\lambda I)
\end{eqnarray*}
\end{definition}

The eigenvectors for $\lambda$ are the non-zero vectors in the null space of $A-\lambda I$: the vectors it sends to $\vec{0}$.
\end{frame}



%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Why At Most n Eigenvalues}
\begin{theorem}
 A scalar $\lambda$ is an eigenvalue of an $n\times n$ matrix $A$ if and only if 
$\lambda$ satisfies the \underline{characteristic equation} 
\[
 \det(A -\lambda I) = 0.
\]
\end{theorem}


\begin{theorem}
$\det(A-\lambda I)$ is a polynomial in $\lambda$ of degree $n$.   \\
Hence, an $n\times n$ matrix has at most $n$ eigenvalues.
\end{theorem}

\begin{block}{Intuition}
Solving $\det(A-\lambda I) = 0$ is really asking: for which stretch factor $\lambda$ does $A$
have a direction it only scales, never rotates? Since a degree-$n$ polynomial has at most $n$
roots, an $n \times n$ matrix has at most $n$ such special directions: exactly the
eigenvectors PCA sorts by eigenvalue to find its principal components.
\end{block}
\end{frame}

\begin{frame}[fragile]\frametitle{Verifying an Eigenvector}
For the matrix
\[
A = \begin{bmatrix} -6 & 3 \\ 4 & 5 \end{bmatrix},
\]
an eigenvector is $v = \begin{bmatrix} 1 \\ 4 \end{bmatrix}$ with matching eigenvalue $\lambda = 6$. Check:
\[
Av =
\begin{bmatrix} -6 & 3 \\ 4 & 5 \end{bmatrix}
\begin{bmatrix} 1 \\ 4 \end{bmatrix}
=
\begin{bmatrix} -6 \times 1 + 3 \times 4 \\ 4 \times 1 + 5 \times 4 \end{bmatrix}
=
\begin{bmatrix} 6 \\ 24 \end{bmatrix}
\]
\[
\lambda v = 6
\begin{bmatrix} 1 \\ 4 \end{bmatrix}
=
\begin{bmatrix} 6 \\ 24 \end{bmatrix}
\]
They are equal, so $Av = \lambda v$ as promised.

{\tiny (Ref: Eigenvector and Eigenvalue - Maths is fun)}
\end{frame}

% %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Solving for the Eigenvalues}
Start with $|A - \lambda I| = 0$:
\[
\begin{vmatrix} -6-\lambda & 3 \\ 4 & 5-\lambda \end{vmatrix} = 0
\]
Calculating the determinant gives a quadratic equation:
\[
(-6-\lambda)(5-\lambda) - 3 \times 4 = 0
\quad\Rightarrow\quad
\lambda^2 + \lambda - 42 = 0
\]
Solving it:
\[
\lambda = -7 \text{ or } 6
\]
There are two possible eigenvalues.

{\tiny (Ref: Eigenvector and Eigenvalue - Maths is fun)}
\end{frame}

\begin{frame}[fragile]\frametitle{Finding the Eigenvector}
Find the eigenvector for the eigenvalue $\lambda = 6$. Start with $Av = \lambda v$:
\[
\begin{bmatrix} -6 & 3 \\ 4 & 5 \end{bmatrix}
\begin{bmatrix} x \\ y \end{bmatrix}
= 6
\begin{bmatrix} x \\ y \end{bmatrix}
\quad\Rightarrow\quad
\begin{aligned} -6x + 3y &= 6x \\ 4x + 5y &= 6y \end{aligned}
\]
Bringing everything to the left-hand side:
\[
\begin{aligned} -12x + 3y &= 0 \\ 4x - y &= 0 \end{aligned}
\]
Either equation gives $y = 4x$, so the eigenvector is any non-zero multiple of
\[

\begin{frame}[fragile]\frametitle{Why?}
What is the purpose of these?

\begin{itemize}
\item For a transformation matrix, an eigenvector is ``the direction that stays on the same line''
\item And the eigenvalue is the scale of the stretch:
\begin{itemize}
\item 1 means no change,
\item 2 means doubling in length,
\item -1 means pointing backwards along the same line
\item etc
\end{itemize}
\item Mechanics example: principal stresses are the eigenvalues of the stress tensor, and the principal directions are its eigenvectors
\end{itemize}

{\tiny (Ref: Eigenvector and Eigenvalue - Maths is fun)}
\end{frame}

\begin{itemize}
\item Eigen is a German word meaning ``own'' or ``typical'': ``das ist ihnen eigen'' is German for ``that is typical of them''
\item Sometimes in English we use the word ``characteristic'', so an eigenvector can be called a ``characteristic vector''.
\end{itemize}

\begin{frame}[fragile]\frametitle{Quick Check: Eigenvectors in PCA}
\begin{block}{Think About It}
Back in the context of PCA applied to a covariance matrix: what do its eigenvectors and
eigenvalues represent?
\begin{enumerate}
  \item[A.] The eigenvectors are the original data points, and the eigenvalues are their
  coordinates.
  \item[B.] The eigenvectors point along the principal component directions, and each
  eigenvalue is the amount of variance captured along that direction.
  \item[C.] The eigenvectors are the mean of the data, and the eigenvalues are its standard
  deviation.
  \item[D.] Eigenvectors and eigenvalues only apply to square matrices, so they're unrelated
  to PCA, which works on rectangular data.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Eigenvectors in PCA}
\begin{block}{Answer}
\textbf{Correct: B.} The covariance matrix is $p \times p$, always square, so it always has
eigenvectors/eigenvalues to find. Each eigenvector is a direction in the original feature
space; its matching eigenvalue says how much variance the data has along that direction.
Sorting eigenvectors by their eigenvalues, largest first, is exactly how PCA ranks its
principal components.
\end{block}
\end{frame}

\begin{frame}[fragile] \frametitle{Practical Scenario}

Suppose we want to reduce the dimensionality of our dataset from 5 features to 2. The procedure is:

\begin{itemize}
\item Compute the covariance matrix $C$ of our data: it is $5 \times 5$
\item Compute the matrix of eigenvectors and the corresponding eigenvalues
\item Sort the eigenvectors by eigenvalue, in descending order
\item Build the projection matrix $W$ from the $k$ eigenvectors we keep ($k = 2$ here)
\begin{itemize}
\item Here $W$ is a $5 \times 2$ matrix; in general it is $d \times k$
\item $d$ = number of original features, $k$ = number of kept features
\end{itemize}
\item Transform the data: the original data is an $n \times d$ matrix $X$ ($n$ = number of observations)
\begin{itemize}
\item Multiplying by $W$ gives the new dataset $X'$, of size $n \times k$
\end{itemize}
\end{itemize}

{\tiny (Ref: PCA: Eigenvectors and Eigenvalues - Valentina Alto)}

\end{frame}

\begin{frame}[fragile] \frametitle{Choosing Components}
\begin{itemize}
\item The eigenvector with the highest eigenvalue is the first principal component.
\item Here, it points down the middle of the data.
\item Order the eigenvectors by eigenvalue, highest to lowest.
\item That is the order of significance.
\item Keep the important ones.
\item Small eigenvalues are ignorable.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{How Much Do We Keep?}
\begin{itemize}
\item Each eigenvalue is the variance along its component
\item Explained variance ratio of component $i$: $\dfrac{\lambda_i}{\lambda_1 + \lambda_2 + \cdots + \lambda_p}$
\begin{itemize}
\item In words: the share of the total variance that component carries
\end{itemize}
\item Here the eigenvalues are $1.284$ (first component) and $0.049$ (second); together $1.333$
\begin{itemize}
\item First component: $1.284 / 1.333 = 96.3\%$ of the variance
\item Second component: $0.049 / 1.333 = 3.7\%$
\end{itemize}
\item Keeping only the first component loses just $3.7\%$ of the variance
\item Rule of thumb: keep enough components to explain 90 to 95\% of the variance
\item A scree plot (variance per component) shows where extra components stop helping
\end{itemize}
\end{frame}

{\Large Formal View and Wrap-Up}
\end{center}
\end{frame}

\begin{frame}[fragile] \frametitle{The First Component, Formally}

\begin{itemize}
\item A principal component is a normalized linear combination of the original features.
\item The first principal component can be written as:
$Z_1 = w_{11}X_1 + w_{21}X_2 + \ldots +  w_{p1}X_p$
\begin{itemize}
\item In words: a new feature built as a weighted sum of the old features
\item Normalized: the weights satisfy $w_{11}^2 + w_{21}^2 + \ldots + w_{p1}^2 = 1$
\end{itemize}
\item It captures the maximum variance in the data set.
\item It determines the direction of highest variability in the data.
\item The more variance a component captures, the more information it carries.
\item No other component can have more variance than the first principal component.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Second Component, Formally}

\begin{itemize}
\item The first principal component gives the line closest to the data, i.e. it minimizes the sum of squared distances between a data point and the line.
\item Similarly, we can compute the second principal component:
$Z_2 = w_{12}X_1 + w_{22}X_2 + \ldots +  w_{p2}X_p$
\item It is built orthogonal (perpendicular) to the first, which makes the two components uncorrelated
\begin{center}
\includegraphics[width=0.65\linewidth,keepaspectratio]{pca3}
\end{center}
\item Each later component captures the remaining variation and is uncorrelated with all earlier components.
\end{itemize}

\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Dropping Minor Components}
Can ignore the components of lesser significance.
\begin{center}
\includegraphics[width=\linewidth,keepaspectratio]{pca7}
\end{center}
You do lose some information, but if the eigenvalues are small, you don't lose 
much.
\end{frame}

\begin{frame}[fragile] \frametitle{Computing It with SVD}
\begin{itemize}
\item Singular Value Decomposition (SVD) factors the centered data matrix $X$ ($n$ samples, $d$ features): $X = U \Sigma V^{\top}$
\begin{itemize}
\item The columns of $V$ are the principal component directions: the eigenvectors of the covariance matrix
\item The singular values give the eigenvalues: $\lambda_i = \sigma_i^2 / (n-1)$
\item The projected data (scores) are $U\Sigma = XV$
\end{itemize}
\item SVD works on the data directly, so it never builds the $d \times d$ covariance matrix, and it stays accurate when features are nearly redundant
\item scikit-learn picks a solver automatically: full SVD, randomized SVD, or the covariance route for tall data with few features
\item Result: the same components and variances either way
\end{itemize}
\end{frame}

\begin{frame}[fragile]
\frametitle{Advantages}
Advantages
\begin{itemize}
	\item Useful pre-processing step
	\item Reduces computational complexity
	\item Noise reduction
	\item Removes correlated (redundant) features
	\item Makes high-dimensional data visualizable in 2-D or 3-D
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]
\frametitle{Limitations}
Limitations
\begin{itemize}
	\item Finds linear structure only (straight-line combinations of the features)
	\item Components are mixtures of features, so they can be hard to interpret
	\item Variance is not relevance: PCA ignores the target, so the top components may not be the most predictive
	\item Sensitive to feature scale and to outliers
	\item The covariance matrix is huge for many features, so finding its eigenvectors is slow
	\item SVD (Singular Value Decomposition, a matrix factorization that gives the same components without forming the covariance matrix) comes to the rescue
\end{itemize}
\end{frame}



%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{A Look Ahead}

\begin{itemize}
\item The main shortcoming of principal components is that they capture only global linear structure in the data
\begin{itemize}
\item This tends to be a larger problem for prediction than for visualization
\end{itemize}
\item Non-linear extensions exist and are an active area of research, for example:
\begin{itemize}
\item Kernel PCA
\item t-SNE and UMAP (mainly for visualization)
\item Autoencoders (neural networks that learn a compressed representation)
\item Locally linear embedding
\item Diffusion maps
\end{itemize}
\end{itemize}

\end{frame}

\begin{frame}[fragile]\frametitle{Quick Check: Standardizing Before PCA}
\begin{block}{Think About It}
You run PCA directly on a dataset with ``income'' (range \$10K-\$1M) and ``age'' (range
18-80), without standardizing first. What will likely go wrong, and why?
\begin{enumerate}
  \item[A.] Nothing; PCA is scale-invariant by default.
  \item[B.] The first principal component will be dominated by income's huge numeric range,
  effectively drowning out age's real contribution to the data's structure.
  \item[C.] PCA will fail to run entirely, since eigenvalues can't be computed for features
  with different units.
  \item[D.] PCA automatically standardizes the data internally before computing the
  covariance matrix.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Standardizing Before PCA}
\begin{block}{Answer}
\textbf{Correct: B.} PCA maximizes captured variance, and raw income values vary by
hundreds of thousands while raw age varies by tens: the covariance matrix, and so the first
eigenvector, will be dominated by income's scale, not by which features are actually most
informative. This is exactly why ``Standardize the data'' is Step 1 of the PCA recipe, not
an afterthought. (scikit-learn's \texttt{PCA} centers the data but does not scale it, so option D is false.)
\end{block}
\end{frame}
