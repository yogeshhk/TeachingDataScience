\begin{frame}[fragile]\frametitle{Why Plain Retrieval Is Not Enough}
\begin{itemize}
\item Usual recipe (RAG, retrieval-augmented generation): cut the text into fixed windows, embed them, fetch the top few, let the model answer.
\item Some answers sit in no window: ``mandatory'' or ``optional'' can live in a table's header rows, not in a column.
\item Some answers are spread out: ``which courses mention a topic?'' needs a join over all courses; top-few retrieval cannot join.
\item Bullet levels (topic, subtopic) often show only as indentation.
\item Idea: recover the structure first, answer exact questions from it, keep the model for wording.
\end{itemize}
{\tiny (Ref: FrugalAI code/quantum-wiki)}
\end{frame}

\begin{itemize}
\item Parse once with Docling and keep the lossless document: text, tables with their spans, and the position of every list item. Cache it, do not re-parse per question.
\item Read the table's spanning rows (cells that repeat across columns) as group headers. Read list levels from indentation, not from the bullet glyph.
\item Build one ``card'' per course: status, credits, topic tree, outcomes, references, page numbers.
\end{itemize}

\begin{frame}[fragile]\frametitle{Implementation: Chunks, Embeddings, Retrievers}
\begin{itemize}
\item \textbf{Chunks}: one per module, from the cards. Each starts with a header line (course code, title, section) and carries its page numbers.
\item \textbf{Embeddings}: a small local embedding model (in LM Studio) turns each chunk into a list of numbers that captures meaning. Cached on disk.
\item \textbf{Retrievers}: three, to compare:
	\begin{itemize}
	\item \textbf{Dense}: finds chunks whose embedding is close to the question's (similar meaning).
	\item \textbf{BM25}: a keyword-scoring method, the successor of TF-IDF. A chunk scores higher when it has the question's words; rare words count more, repeats count less, long chunks are evened out. It matches words, not meaning, and uses no embeddings.
	\item \textbf{Hybrid}: merges the two rankings (reciprocal-rank fusion). Do not assume it wins.
	\end{itemize}
\item Documents and retrievers are LangChain objects; the cards and tools are plain Python.
\end{itemize}
{\tiny (Ref: LangChain 1.x; LM Studio local server; FrugalAI code/quantum-wiki)}
\end{frame}

\begin{frame}[fragile]\frametitle{Implementation: Tools First, Model Second, Then Check}
\begin{itemize}
\item A rule-based router sends each question to a tool (course status, credits, ``which courses mention X'', references, topic tree). No rule fires: fall back to retrieval.
\item Tools give an exact answer from the structure, with no model call. The model reads a course's text only for open topic questions.
\item Check in plain code: every course code and name in an answer must occur in the evidence; else retry once, then refuse.
\item Nothing found: say ``the syllabus does not say''. Never let the model fill the gap.
\item Evaluate with a gold question set (answers and pages), a separate set of reworded questions, and plain baselines on the same questions.
\end{itemize}
