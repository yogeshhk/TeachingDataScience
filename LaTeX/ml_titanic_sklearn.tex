\begin{frame}[fragile]\frametitle{The Titanic Disaster: Background}
\begin{itemize}
\item The sinking of the Titanic is one of the most infamous shipwrecks in history.
\item It sank after colliding with an iceberg, killing 1502 out of 2224 passengers and crew.
\item One of the reasons for loss of life was that there were not enough lifeboats for the passengers and crew. 
\item Some groups of people were more likely to survive than others, such as women, children, and the upper-class.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{The Titanic Competition: Train vs Test Data}
\begin{itemize}
\item Each Kaggle competition has two key data files that you will work with - a training set and a testing set.
\item The training set contains data we can use to train our model. 
\item It has a number of feature columns which contain various descriptive data, as well as a column of the target values we are trying to predict: in this case, Survival.
\item The testing set contains all of the same feature columns, but is missing the target value column. Additionally, the testing set usually has fewer observations (rows) than the training set.
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Data Dictionary}
Below are the descriptions contained in that data dictionary
\begin{itemize}
\item PassengerID: A column added by Kaggle to identify each row
\item Survived: Passenger survived or not (0=No, 1=Yes)
\item Pclass: The class of the ticket (1=1st, 2=2nd, 3=3rd)
\item Sex: The passenger's sex
\item Age: The passenger's age in years
\item SibSp: The number of siblings or spouses 
\item Parch: The number of parents or children
\item Ticket: The passenger's ticket number
\item Fare: The fare the passenger paid
\item Cabin: The passenger's cabin number
\item Embarked: The port where the passenger embarked (C=Cherbourg, Q=Queenstown, S=Southampton)
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Fill Missing Ages}
Determine the Age typical for each passenger class by Sex\_Val. We'll use the median instead of the mean because the Age histogram seems to be right skewed.
\begin{lstlisting}
# Keep Age intact: AgeFill is a copy where each missing age is replaced
# by the median age of that (Sex_Val, Pclass) group
df_train['AgeFill'] = df_train.groupby(['Sex_Val', 'Pclass'])['Age'] \
                              .transform(lambda x: x.fillna(x.median()))
\end{lstlisting}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Why Did Accuracy Drop?}
\begin{block}{Think About It}
The random forest scored 98\% accuracy when evaluated on the full training data, but only
84\% on the held-out 20\% split. Why the big gap, and which number should you actually
trust to predict how the model will do on Kaggle's real test set?
\begin{enumerate}
  \item[A.] The 84\% number is wrong; the model is really 98\% accurate, the split just got
  unlucky.
  \item[B.] The 98\% reflects memorization of data the model already saw during training; the
  84\% reflects performance on unseen data, which is what actually matters.
  \item[C.] Random forests are inherently unstable, so both numbers are meaningless.
  \item[D.] The gap is caused by the confusion matrix, not by the train/test split.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Why Did Accuracy Drop?}
\begin{block}{Answer}
\textbf{Correct: B.} A random forest with 100 trees has plenty of capacity to fit quirks of
the exact 891 training rows it saw, so scoring it on that same data mostly measures
memorization, not learning. The 84\% figure, measured on the 179 rows held out of training,
is the honest estimate of how the model performs on data it hasn't memorized: closer to what
Kaggle's actual (unseen) test set will show.
\end{block}
\end{frame}

\begin{frame}[fragile]\frametitle{Classification Report}
Display the classification report:
\begin{itemize}
\item Precision: of the passengers predicted to survive, the share who did (49 of 58 = 0.84)
\item Recall: of the passengers who did survive, the share we found (49 of 69 = 0.71)
\item F1-score: one number that balances precision and recall; support: how many passengers of that class
\end{itemize}
\begin{lstlisting}

>>> print(classification_report(test_y, predict_y,
...                             target_names=['Not Survived', 'Survived']))

Not Survived       0.83      0.92      0.87       110
    Survived       0.84      0.71      0.77        69

    accuracy                           0.84       179
   macro avg       0.84      0.81      0.82       179
weighted avg       0.84      0.84      0.83       179
\end{lstlisting}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Reading the Classification Report}
\begin{block}{Think About It}
Recall is 0.92 for ``Not Survived'' but only 0.71 for ``Survived'', even though both classes
get the same model. What's the most likely reason the model is worse at correctly finding
survivors specifically?
\begin{enumerate}
  \item[A.] The model is broken and should be retrained from scratch.
  \item[B.] ``Survived'' has fewer training examples (roughly 38\% of the 891 passengers), so
  the model has seen fewer patterns for that class and defaults toward the majority class
  more often.
  \item[C.] Recall and precision are unrelated to how much training data each class has.
  \item[D.] The 179-row test split happened to contain zero survivors.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Reading the Classification Report}
\begin{block}{Answer}
\textbf{Correct: B.} This is a mild class-imbalance effect: ``support'' in the report shows
110 Not-Survived rows versus only 69 Survived rows in this test split, mirroring the full
dataset's roughly 62/38 split. With fewer survivor examples to learn from, the model is more
prone to guessing ``Not Survived'', which raises that class's recall while lowering
survivors' recall. This is the same class-imbalance idea worth watching for whenever one
outcome is rarer than the other.
\end{block}
\end{frame}

\begin{frame}[fragile]\frametitle{Cross-Validation}
\begin{itemize}
\item One 80/20 split gives one number, and it depends on which rows landed in the test set
\item Cross-validation repeats the split: train on 4 parts, test on the 5th, and rotate 5 times
\item Report the mean and the spread of the 5 scores
\end{itemize}
\begin{lstlisting}
from sklearn.model_selection import cross_val_score

clf = RandomForestClassifier(n_estimators=100, random_state=0)
scores = cross_val_score(clf, train_features, train_target, cv=5)

# In the Python shell:
>>> print(scores.round(3))
[0.777 0.803 0.854 0.803 0.848]
>>> print("Accuracy: %.3f +/- %.3f" % (scores.mean(), scores.std()))
Accuracy: 0.817 +/- 0.030
\end{lstlisting}
\end{frame}
