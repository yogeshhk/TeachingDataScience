\begin{frame}[fragile]\frametitle{Support Vector Machines (SVM)}
\begin{itemize}
\item Support vector machines are supervised machine learning algorithms that construct
separating planes for classification.
\item They are conceptually fairly simple, but the underlying mathematics for learning them from data can be tricky.
\end{itemize}
\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Support Vector Machines (SVM) Inventors}
\begin{itemize}
\item See video ``Vladimir Vapnik - 2012 Laureate of the Franklin Institute in Computer and Cognitive Science'' at Youtube.
\item Vladimir Vapnik discusses how his early years in Moscow helped shaped the origins of statistical learning theories, including the ideas behind the SVM.
\item His collaborator, Isabelle Guyon, also discusses the Kernel Trick, which generalized the SVMs for non-linear decision boundaries (hence making them more popular). In her own words:
\end{itemize}
\small{
``The invention of SVMs happened when Bernhard decided to implement Vladimir’s algorithm in the three months we had left before we moved to Berkeley. After some initial success of the linear algorithm, Vladimir suggested introducing products of features. I proposed to rather use the kernel trick of the ‘potential function’ algorithm. Vladimir initially resisted the idea because the inventors of the ‘potential functions’ algorithm (Aizerman, Braverman, and Rozonoer) were from a competing team of his institute back in the 1960’s in Russia!'' - Isabelle Guyon
}
\end{frame}

\begin{frame}[fragile]\frametitle{Support Vector Machines (SVM)}
SVMs are the combination of two ideas
	\begin{itemize}
	\item Maximum margin classification: among all possible separating boundaries, pick the one that stays as far as possible from every training point.
	\item The ``kernel trick'': a way to draw a non-linear boundary by implicitly working in a higher-dimensional space, without ever computing that space explicitly.
	\end{itemize}
The rest of this section builds up exactly how each of these two ideas works, starting with maximum margin classification.
\end{frame}

\begin{frame}[fragile] \frametitle{SVM Intuition: The Hyperplane Equation}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm11}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item Goal is to find a separating plane that separates the classes as per the training data
\item Generic Hyper-plane's equation is taken as $g(\overrightarrow{x}) = \overrightarrow{w}^T \overrightarrow{x}+ w_0$
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Intuition: Class Boundaries on g(x)}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm14}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item For data points labeled as circles, when features are put into ``g'' equation, the result is more than equal to 1
\item For data points labeled as squares, when features are put into ``g'' equation, the result is less than equal to -1
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Intuition: Distance to the Hyperplane}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm15}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item Distance of a point from a hyper-plane is $z$
\item Given by a formula $z = \frac{|g(x)|}{||w||}$, is also called `margin'
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Intuition: Distance, Worked Example}
\begin{block}{Worked Example}
Say $\vec{w}=(1,1)$, $w_0=-2$, and a point $\vec{x}=(3,3)$. Then
\[
g(\vec{x}) = 1(3) + 1(3) - 2 = 4
\]
\[
z = \frac{|g(\vec{x})|}{\|\vec{w}\|} = \frac{|4|}{\sqrt{1^2+1^2}} = \frac{4}{\sqrt{2}} \approx 2.83
\]
\end{block}
\begin{itemize}
\item So this particular point sits about $2.83$ units away from the hyperplane $g(\vec{x})=0$.
\item A point exactly on the hyperplane would have $g(\vec{x})=0$, so $z=0$: zero distance, as expected.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Intuition: The Full Margin Width}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm16}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item For any point, $g(\overrightarrow{x})$ is atleast ``1'', on either side (this is the minimum-est, g(x) can get, from the formula)
\item So min distance on either side is $\frac{1}{||\overrightarrow{w}||}$
\item Total margin from both sides is $\frac{2}{||\overrightarrow{w}||}$
\item So, if we minimize $\overrightarrow{w}$, then margin will be maximum.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Example: Setting Up the Weight Vector}

\begin{center}
\includegraphics[width=0.5\linewidth]{svm19}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item We know that the hyper-plane line would be equidistant from two closest points (2,3) and (1,1)
\item So, generically the weight vector would be of the form $ \bar{w} = (2,3) - (1,1) = (a,2a)$
\item Need to find $a$ and then $\bar{w}, w_0$
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Example: Solving for w and w0}
\begin{itemize}
\item Weight vector $\bar{w} = (a,2a)$; plug in both labeled points using $g(\bar{x}) = \bar{w}\cdot\bar{x} + w_0$.
\end{itemize}
\begin{align*}
\text{Negative point } (1,1): \quad & a + 2a + w_0 = -1 \;\; \Rightarrow \;\; 3a + w_0 = -1\\
\text{Positive point } (2,3): \quad & 2a + 6a + w_0 = 1 \;\; \Rightarrow \;\; 8a + w_0 = 1
\end{align*}
\begin{itemize}
\item Solving simultaneously: from the positive-point equation, $w_0 = 1-8a$.
\end{itemize}
\begin{align*}
3a + (1-8a) &= -1 \\
-5a &= -2 \\
a &= \frac{2}{5}
\end{align*}
\begin{itemize}
\item So $w_0 = 1 - 8\left(\frac{2}{5}\right) = -\frac{11}{5}$, and $\bar{w} = \left(\frac{2}{5},\frac{4}{5}\right)$.
\end{itemize}
\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Example: The Resulting Hyperplane}
\begin{align*}
g(\bar{x}) &= \frac{2}{5}x_1 + \frac{4}{5}x_2 - \frac{11}{5}\\
\text{Setting } g(\bar{x})=0 \text{ and scaling by } \frac{5}{2}: \quad g(\bar{x}) &= x_1 + 2x_2 - 5.5
\end{align*}
\begin{itemize}
\item This is the maximum-margin hyperplane for our 3-point example, plotted natively on the next slide.
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Finding w and w0 Systematically}
\begin{itemize}
\item So far we picked $\bar{w}, w_0$ by hand for a 3-point toy example. For real datasets, we need an algorithm.
\item From here on the same idea is written using $b$ in place of $w_0$, the more common notation in optimization textbooks: equations below read $w^Tx+b$ instead of $g(\vec{x})=w^Tx+w_0$. The underlying idea is identical.
\item Goal: maximize the margin $\frac{2}{||w||}$ while every point is still classified correctly.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Why Do We Need an Algorithm?}
\begin{itemize}
\item Our 3-point example had exactly 2 unknowns ($a$ and $w_0$), so pen-and-paper algebra worked.
\item A real dataset can have hundreds of features and thousands of points. $w$ then has hundreds of unknowns, and we can't just ``eyeball'' which two points are closest.
\item We need a recipe that any computer can follow, for any number of points and features. The next few slides build that recipe, one small step at a time.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{Combining 2 Equations}
\begin{itemize}
\item Recall from before: $g(x)\ge 1$ for one class, $g(x)\le -1$ for the other. Combine both into one inequality by leveraging the label $y_i \in \{+1,-1\}$ itself.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max \frac{2}{\|w\|} \quad \text{while classifying everything correctly:} \quad y_i(w^Tx_i+b) \geq 1 \;\; \forall i
$}
\end{center}
\begin{itemize}
\item The ``plus minus 1'' thing on the right side has changed to just ``plus 1'' because $y_i$ becomes minus if right hand side is minus, and both cancel out!!! Wonderful trick.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{From a Maximization to a Minimization}
\begin{itemize}
\item We want to \emph{maximize} $\frac{2}{\|w\|}$. Making a fraction bigger means making its denominator smaller, so this is exactly the same as \emph{minimizing} $\|w\|$.
\item Working with $\|w\|$ directly involves a square root, which is awkward for optimization software. Instead we minimize $\frac{1}{2}\|w\|^2$.
\end{itemize}
\begin{block}{Intuition}
Squaring doesn't change \emph{where} the minimum is: since $\|w\|\geq 0$ always, whatever $w$
makes $\|w\|$ smallest also makes $\|w\|^2$ smallest. We square purely for mathematical
convenience, it turns a problem with a square root into a smooth ``bowl'' shape that is much
easier for a computer to descend. The $\frac{1}{2}$ is there only to cancel a $2$ that appears
later when we differentiate, it changes nothing about the answer.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Optimization Problem, Plainly}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\min_{w,b} \; \frac{1}{2}\|w\|^2 \qquad \text{subject to} \qquad y_i(w^Tx_i+b) \geq 1 \;\; \forall i
$}
\end{center}
\begin{itemize}
\item In plain words: find the smallest $w$ possible, without ever letting any point cross into the margin.
\item This shape, a smooth bowl-like objective with straight-line constraints, is called \textbf{quadratic programming}. It's a well-studied, decades-old problem class with efficient, reliable solvers: we don't need to invent a new algorithm, we can hand this exact shape to existing software.
\item Being convex (bowl-shaped, no false valleys), it also guarantees a single, unique best answer, no risk of getting stuck in the ``wrong'' minimum.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Enter Lagrange Multipliers}
\begin{itemize}
\item The problem above has one constraint \emph{per training point}: hundreds of points means hundreds of ``don't cross this line'' rules to satisfy simultaneously.
\item The standard trick for this shape of problem: attach one multiplier $\alpha_i \geq 0$ to each point's constraint. Think of $\alpha_i$ as how much ``say'' point $i$ gets in shaping the boundary.
\item This rewrites the problem entirely in terms of the $\alpha_i$'s instead of $w$ directly, this rewritten version is called the \textbf{dual} problem.
\end{itemize}
\begin{block}{Intuition}
Don't get lost in the mechanics: this step just swaps one hard-to-solve problem (find $w,b$
directly, honoring every constraint at once) for an equivalent easier one (find one number
$\alpha_i$ per training point). It turns out most $\alpha_i$ come out as exactly 0, and only
the non-zero ones (the support vectors) end up mattering, that's the whole payoff.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Dual Problem}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max_{\alpha} \; W(\alpha) = \sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, x_i^Tx_j \qquad \text{s.t.} \;\; \alpha_i\geq0,\;\; \sum_i \alpha_i y_i = 0
$}
\end{center}
\begin{itemize}
\item $\sum_i \alpha_i$: a reward for each point's ``say'' $\alpha_i$, bigger alphas score higher.
\item $\frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\,x_i^Tx_j$: a penalty for how much every \emph{pair} of points agrees or disagrees, subtracted off.
\item $\alpha_i\geq0$: no point can have negative ``say''.
\item $\sum_i \alpha_i y_i = 0$: the positive and negative classes' total ``say'' must balance out.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Recovering w and b from the Alphas}
\[
w = \sum_i \alpha_i y_i x_i
\]
\begin{itemize}
\item Once the $\alpha_i$'s are solved for, $w$ falls out directly: it's a weighted combination of the training points, weighted by how much ``say'' ($\alpha_i$) each one has.
\item $b$ is then recovered from any single support vector (any point with $\alpha_i>0$), by plugging it back into $y_i(w^Tx_i+b)=1$ and solving for $b$.
\item So the whole algorithm reduces to: solve for the $\alpha_i$'s, then read off $w$ and $b$.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Support Vectors: Why Most Points Don't Matter}
\[
\alpha_i \text{ mostly } 0 \;\Rightarrow\; \text{few } x_i \text{ matter}
\]
\begin{itemize}
\item Most of the alphas come out as exactly 0. Only the points with $\alpha_i>0$, the \textbf{support vectors}, contribute to $w$.
\item These are exactly the points sitting on (or violating) the margin boundary. Every other point, however far away, could be deleted without changing $w$ or $b$ at all.
\item So this is a machine that only needs to remember its support vectors.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Similarity Term}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max_{\alpha} \; W(\alpha) = \sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \underbrace{x_i^Tx_j}_{\text{similarity}}
$}
\end{center}
\begin{itemize}
\item Points far away DO NOT MATTER, much like Nearest Neighbor where only local points matter, except here we don't have to pick $K$ by hand: quadratic programming tells us exactly which points (and how many) are support vectors.
\item The $x_i^Tx_j$ term is a dot product: large when the two points point in a similar direction, near zero when they're roughly perpendicular. It's a similarity measure between points.
\end{itemize}

\begin{block}{Intuition}
All that algebra, across this whole section, boils down to one idea: instead of solving
directly for the widest gap, we rephrase it as ``minimize $\|w\|$'', a smooth, convex problem
that optimization software already knows how to solve reliably. The reward for the detour is
that the solution turns out to depend on only a handful of training points (the support
vectors); every other point, however far from the boundary, could be deleted without changing
the answer at all.
\end{block}
\end{frame}

\begin{frame}[fragile] \frametitle{Soft Margin: Why We Need It}
\begin{itemize}
\item Everything so far assumed a \textbf{hard margin}: a line that separates the two classes perfectly, with zero mistakes.
\item Real data is messier. One noisy or mislabeled point sitting on the wrong side can mean \emph{no} separating line exists at all, the hard-margin problem has no solution.
\item Even when a perfect line does exist, forcing zero mistakes can mean bending the boundary sharply around a single outlier, hurting how well it generalizes to new points.
\item Fix: allow a controlled number of violations, in exchange for a wider, more robust margin.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Soft Margin: The Slack Variable}
\begin{itemize}
\item Introduce one slack variable $\xi_i \geq 0$ per training point, measuring how much that point is allowed to violate the margin.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{
\begin{tabular}{c|l}
\textbf{Value of $\xi_i$} & \textbf{What it means} \\ \hline
$\xi_i = 0$ & Correctly classified, outside the margin. No penalty. \\
$0 < \xi_i \leq 1$ & Correctly classified, but inside the margin. \\
$\xi_i > 1$ & Misclassified: on the wrong side of the boundary. \\
\end{tabular}
}
\end{center}
\begin{itemize}
\item Each point's constraint relaxes from $y_i(w^Tx_i+b)\geq 1$ to $y_i(w^Tx_i+b)\geq 1-\xi_i$: the point is allowed to fall short by $\xi_i$.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Soft Margin: The Full Objective}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\min \; \frac{1}{2}\|w\|^2 + C\sum_i \xi_i \quad \text{s.t.} \;\; y_i(w^Tx_i+b) \geq 1-\xi_i, \;\; \xi_i \geq 0
$}
\end{center}
\begin{itemize}
\item Two competing goals in one objective: $\frac{1}{2}\|w\|^2$ still wants the widest possible margin, while $C\sum_i \xi_i$ penalizes every violation.
\item $C$ is the knob that balances them: a bigger $C$ makes violations more costly, pushing toward a narrower margin with fewer mistakes; a smaller $C$ tolerates more violations for a wider, more robust margin.
\item This is exactly the ``narrower vs.\ wider margin'' trade-off from the C-parameter slide before, now written as actual math.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{What are Kernel Methods?: The Mapping Idea}

\begin{itemize}
\item The idea is to create nonlinear combinations of the original features to project them onto a higher-dimensional space via a mapping function $\phi(x)$, where the data becomes linearly separable.
\item In the diagram given below, the two-dimensional dataset (X1, X2) is projected into a new three-dimensional feature space (Z1, Z2, Z3) where the classes become separable.
\end{itemize}


\begin{center}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: The Problem}

\begin{itemize}
\item Look back at the dual problem from the optimization section: every single place $x_i$ and $x_j$ appear, they appear together, as a dot product $x_i^Tx_j$.
\item So if we first map every point into the higher-dimensional space with $\phi(x)$ (as on the previous slide), the dual problem would need $\phi(x_i)\cdot\phi(x_j)$ instead of $x_i^Tx_j$.
\item Problem: computing $\phi(x)$ explicitly can be expensive, or in some cases (as we'll see with the RBF kernel) $\phi(x)$ lives in an infinite-dimensional space and can't even be written down.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \underbrace{\overrightarrow{x_{SVi}}\cdot\overrightarrow{x_{SVj}}}_{\text{dot product}}
$}
\end{center}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: The Shortcut}

\begin{itemize}
\item The trick: we never actually need $\phi(x)$ by itself, we only ever need the \emph{result} of $\phi(x_i)\cdot\phi(x_j)$.
\item So replace the dot product with another function computed directly on the original points, without ever forming $\phi$:
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \phi(\overrightarrow{x_{SVi}})\cdot\phi(\overrightarrow{x_{SVj}})
$}
\end{center}
\begin{itemize}
\item If there is a function that can be represented as an inner product of a mapping function, all we will be required to know is that function and not the mapping function. That function is called a \textbf{Kernel Function}.
\end{itemize}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: Why This Matters}
\begin{itemize}
\item We get the full power of working in a higher (even infinite) dimensional feature space, without ever paying the cost of actually computing coordinates in it.
\item Every dot product $x_i^Tx_j$ in every formula we've derived can simply be swapped for a kernel $K(x_i,x_j)$, and the rest of the machinery (the dual, the alphas, the support vectors) stays exactly the same.
\item This is why the kernel trick is considered one of the most elegant ideas in machine learning: a small algebraic substitution unlocks non-linear boundaries from a purely linear algorithm.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{What are Kernel Functions and its different types?}

\begin{itemize}
\item The kernel function computes the dot product of the mapping function directly, without ever computing $\phi(x)$ itself:
\end{itemize}
\[
K(x_i,x_j) = \phi(x_i)\cdot\phi(x_j)
\]
\begin{itemize}
\item Kernel function reduces the complexity of finding the mapping function. It defines the inner product in the transformed space directly, in terms of the original points. Common choices:
\begin{itemize}
\item \textbf{Polynomial kernel}: bends the boundary into curves of a chosen degree, good for data with polynomial-shaped class boundaries.
\item \textbf{Gaussian kernel}: measures similarity as a smooth bell-curve that fades with distance, flexible but can overfit if not tuned.
\item \textbf{Radial basis function (RBF) kernel}: the most commonly used default, a special case of the Gaussian kernel; works well when no linear or polynomial boundary fits.
\item \textbf{Sigmoid kernel}: behaves like a single-layer neural network's activation, less commonly used in practice.
\end{itemize}
\end{itemize}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{\#1 - Multiclass: One-Against-Rest}
\begin{itemize}
\item Assume multi-class data-set with K target classes
\item Decompose into K binary problems
\item Idea: For each target class yi create a single binary problem, with classifier Ci:
Class yi: positive ;
All other classes: negative;
\item Training:
use all instances; each instance used in training each of the Ci classifiers;
\item Testing:
run testing instance through each classifier;
record votes for each yi class (negative prediction is a vote for all other classes);
class with most votes is the predicted class

\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{\#2 - Multiclass: One-Against-One}
\begin{itemize}
\item Assume multi-class data-set with K target classes
\item Train K(K-1)/2 binary classifiers (many more than One-Against-Rest)
\item Idea: Each classifier distinguishes between pair of classes (yi, yj); Classifier ignores records that don't belong to $y_i$ or $y_j$
\item Training: use all instances; each instance only used in training ``relevant classifiers'' (K of them)
\item Testing:
run testing instance through each classifier;
record votes for each $y_i$ class;
class with most votes is the predicted class;
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Quick Check: Support Vector Machine}
\begin{block}{Think About It}
If you added a new training point that lies far from the decision boundary, on the correct
side of the margin, would the SVM's maximum-margin hyperplane change? What does your answer
tell you about how much of the training set actually ``matters'' to an SVM?
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Support Vector Machine}
\begin{block}{Answer}
No: the hyperplane depends only on the support vectors (the points sitting on or violating
the margin). A point that's already correctly classified with room to spare gets an alpha of
0 in the dual solution, so adding or removing it changes nothing. This is why SVMs can
generalize well from relatively few ``boundary case'' examples, most of the training data
turns out to be redundant once the support vectors are known.
\end{block}
\end{frame}

\begin{frame}[fragile]\frametitle{SVM (Recap) }
\begin{itemize}
\item Maximum Margin Classifier is natural way to perform classification if a separating hyper-plane exists.
\item This generalization is called: support vector classifier
\item In many cases, no separating hyper-plane will exist. So need  to loosen a bit.
\item Maximal Margin Classifier: no training errors allowed
\item Support Vector Classifier: tolerate training errors. Approach: Soft margin
\item Will allow construction of linear decision boundary even when classes are not linearly separable. Kernel Tricks.
\end{itemize}

\end{frame}
