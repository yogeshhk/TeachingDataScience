\begin{frame}[fragile]\frametitle{Support Vector Machines (SVM)}
\begin{itemize}
\item A supervised learning algorithm for classification (and regression) that finds the boundary between classes with the widest possible margin, the largest buffer, to the nearest training points.
\item Why it matters: a boundary chosen for maximum margin tends to generalize better to new, unseen data than one that just barely manages to separate the training set.
\item SVMs combine two ideas:
\begin{itemize}
\item \textbf{Maximum margin classification}: among all possible separating boundaries, pick the one that stays as far as possible from every training point.
\item The \textbf{kernel trick}: a way to draw a non-linear boundary by implicitly working in a higher-dimensional space, without ever computing that space explicitly.
\end{itemize}
\item The rest of this section builds up exactly how each of these two ideas works, starting with maximum margin classification.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Support Vector Machines (SVM) Inventors}
\begin{itemize}
\item \textbf{1963}: Vladimir Vapnik and Alexey Chervonenkis introduce the original maximal margin classifier for linearly separable data, growing out of the statistical (VC) learning theory they developed at the Institute of Control Sciences, Moscow.
\item \textbf{1992}: Bernhard Boser, Isabelle Guyon, and Vladimir Vapnik publish ``A Training Algorithm for Optimal Margin Classifiers'', introducing the \textbf{kernel trick} that lets the same idea handle non-linear boundaries.
\item \textbf{1995}: Corinna Cortes and Vladimir Vapnik formalize the \textbf{soft margin}, allowing controlled misclassifications, turning SVMs into the practical, widely used algorithm known today.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{A Better Threshold: The Margin}
\begin{itemize}
\item Instead, use the two edge observations, the closest not-obese point and the closest obese point, and place the threshold at their midpoint.
\item Now a new observation just left of the threshold is closer to the not-obese cluster than to the obese one, so classifying it not obese makes sense.
\end{itemize}

\textbf{Terminology alert:} the shortest distance between the observations and the threshold is called the \textbf{margin}. Placing the threshold halfway between the two edge points makes the margin on each side equal, and as large as possible.
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Maximal Margin Classifier}
\begin{itemize}
\item Moving the threshold left shrinks the margin on the not-obese side; moving it right shrinks the margin on the obese side.
\item The threshold that gives the largest possible margin is called the \textbf{Maximal Margin Classifier}.
\item It looks good here, but what happens when the training data has an outlier?
\end{itemize}
\end{frame}

\item Suppose one not-obese mouse (red) happens to sit right next to the obese cluster.

\begin{itemize}
\item The maximal margin classifier is now squeezed right up against the obese cluster, far from most of the not-obese points.
\item A new point here would be classified not obese, even though it is much closer to most of the obese observations. Maximal margin classifiers are super sensitive to outliers.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Why This Happens: Bias and Variance}
\begin{itemize}
\item A maximal margin classifier is placed to fit the training data as exactly as possible: it has \textbf{low bias}.
\item But that also means one different, or noisy, training sample can swing the threshold a long way, so it has \textbf{high variance}: it performs poorly on new data.
\item This is the same bias-variance trade-off that shows up everywhere else in machine learning, and the fix is the same one: give up a little fit on the training data in exchange for stability.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{Allowing Misclassifications: The Soft Margin}
\begin{itemize}
\item To make the threshold less sensitive to outliers, we allow some misclassifications on purpose.
\end{itemize}
\begin{center}

\node[above,blue] at (3.95,0.7) {\small threshold};

\node[below] at (3.3,-0.5) {\tiny new point};
\end{tikzpicture}

\end{center}
\begin{itemize}
\item With the threshold back near the middle, the outlier gets misclassified, but a new point here is now correctly classified obese, since it is closer to most of the obese observations.
\item The distance between the observations and this kind of threshold is called a \textbf{soft margin}.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Bias and Variance: The Trade-off, Side by Side}
\begin{center}
\adjustbox{max width=\linewidth}{
\begin{tabular}{l|c|c}
 & \textbf{Maximal Margin Classifier} & \textbf{Soft Margin Classifier} \\ \hline
Fits training data & Very tightly (0 mistakes) & Loosely (allows mistakes) \\
Bias & Low & Higher \\
Variance & High & Lower \\
On new data & Performs poorly & Performs better \\
\end{tabular}
}
\end{center}
\begin{itemize}
\item Choosing to allow misclassifications is a direct application of the bias-variance trade-off that shows up throughout machine learning.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{How Much Softness? Cross-Validation Decides}
\begin{itemize}
\item How many misclassifications should the soft margin allow? Too few and we are back to being sensitive to outliers; too many and the boundary stops meaning anything.
\item The answer: try different amounts of softness and use \textbf{cross-validation} to pick the one that classifies new data best.
\item This is exactly the parameter $C$ used later in this deck (see ``Constructing the Support Vector Classifier''): a bigger $C$ allows fewer violations, closer to a hard margin; a smaller $C$ allows more.
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Quick Check: SVM Intuition}
\begin{block}{Think About It}
A dataset has one clear outlier. You must pick between a threshold with zero training
mistakes (hugging the outlier) and one that deliberately misclassifies the outlier but sits
comfortably in the middle of both clusters. Which one should you expect to perform better on
new data, and why?
\begin{enumerate}
\item[A.] The zero-mistake threshold, since fewer training errors always means a better model.
\item[B.] The threshold that misclassifies the outlier, since it has lower variance and will
generalize better even though it has slightly higher bias.
\item[C.] They perform identically, since both correctly classify the vast majority of points.
\item[D.] It's impossible to know without seeing the test data first.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: SVM Intuition}
\begin{block}{Answer}
\textbf{Correct: B.} The zero-mistake threshold is a maximal margin classifier: it fits this
one training sample perfectly (low bias) but is so sensitive to the outlier that a slightly
different sample would swing it a long way (high variance). Allowing the one misclassification
trades a little bias for a lot less variance, which is the better deal on new data. Option A
mistakes ``fewer training errors'' for ``better generalization'', exactly the trap this section
is about.
\end{block}
\end{frame}

\begin{frame}[fragile] \frametitle{SVM Derivation: The Hyperplane Equation}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm11}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item Goal is to find a separating plane that separates the classes as per the training data
\item Generic Hyper-plane's equation is taken as $g(\overrightarrow{x}) = \overrightarrow{w}^T \overrightarrow{x}+ w_0$
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Derivation: Class Boundaries on g(x)}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm14}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item For data points labeled as circles, when features are put into ``g'' equation, the result is more than equal to 1
\item For data points labeled as squares, when features are put into ``g'' equation, the result is less than equal to -1
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Derivation: Distance to the Hyperplane}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm15}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item Distance of any point from the hyper-plane is $z$, given by $z = \frac{|g(x)|}{||w||}$
\item The \textbf{margin} is this same distance measured for the \emph{closest} training point on each side, not any arbitrary point
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{SVM Derivation: Distance, Worked Example}
\begin{block}{Worked Example}
Say $\vec{w}=(1,1)$, $w_0=-2$, and a point $\vec{x}=(3,3)$. Then
\[
g(\vec{x}) = 1(3) + 1(3) - 2 = 4
\]
\[
z = \frac{|g(\vec{x})|}{\|\vec{w}\|} = \frac{|4|}{\sqrt{1^2+1^2}} = \frac{4}{\sqrt{2}} \approx 2.83
\]
\end{block}
\begin{itemize}
\item So this particular point sits about $2.83$ units away from the hyperplane $g(\vec{x})=0$.
\item A point exactly on the hyperplane would have $g(\vec{x})=0$, so $z=0$: zero distance, as expected.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{SVM Derivation: The Full Margin Width}

\begin{center}
\includegraphics[width=0.6\linewidth]{svm16}

\tiny{(Ref: How Classification Algorithms Work? - Thales Sehn Korting)}
\end{center}
\begin{itemize}
\item For any point, $g(\overrightarrow{x})$ is at least $1$ in magnitude, on either side; that is the smallest value the formula allows
\item So min distance on either side is $\frac{1}{||\overrightarrow{w}||}$
\item Total margin from both sides is $\frac{2}{||\overrightarrow{w}||}$
\item So, if we minimize $\overrightarrow{w}$, then margin will be maximum.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{SVM Example: Solving for w and w0}
\begin{itemize}
\item Weight vector $\bar{w} = (a,2a)$; plug in both labeled points using $g(\bar{x}) = \bar{w}\cdot\bar{x} + w_0$.
\end{itemize}
\begin{align*}
\text{Negative point } (1,1): \quad & a + 2a + w_0 = -1 \;\; \Rightarrow \;\; 3a + w_0 = -1\\
\text{Positive point } (2,3): \quad & 2a + 6a + w_0 = 1 \;\; \Rightarrow \;\; 8a + w_0 = 1
\end{align*}
\begin{itemize}
\item Solving simultaneously: from the positive-point equation, $w_0 = 1-8a$.
\end{itemize}
\begin{align*}
3a + (1-8a) &= -1 \\
-5a &= -2 \\
a &= \frac{2}{5}
\end{align*}
\begin{itemize}
\item So $w_0 = 1 - 8\left(\frac{2}{5}\right) = -\frac{11}{5}$, and $\bar{w} = \left(\frac{2}{5},\frac{4}{5}\right)$.
\end{itemize}

In the 3-point worked example, the boundary was placed exactly equidistant from $(1,1)$ and

optimal margin.
\item[B.] The boundary would stay exactly the same, since $(2,0)$ was never a support point.
\item[C.] The boundary would disappear, since a point that far away breaks the margin formula.

\begin{frame}[fragile]\frametitle{Finding w and w0 Systematically}
\begin{itemize}
\item So far we picked $\bar{w}, w_0$ by hand for a 3-point toy example. For real datasets, we need an algorithm.
\item From here on the same idea is written using $b$ in place of $w_0$, the more common notation in optimization textbooks: equations below read $w^Tx+b$ instead of $g(\vec{x})=w^Tx+w_0$. The underlying idea is identical.
\item Goal: maximize the margin $\frac{2}{||w||}$ while every point is still classified correctly.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Why Do We Need an Algorithm?}
\begin{itemize}
\item Our 3-point example had exactly 2 unknowns ($a$ and $w_0$), so pen-and-paper algebra worked.
\item A real dataset can have hundreds of features and thousands of points. $w$ then has hundreds of unknowns, and we can't just ``eyeball'' which two points are closest.
\item We need a recipe that any computer can follow, for any number of points and features. The next few slides build that recipe, one small step at a time.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{Combining 2 Equations}
\begin{itemize}
\item Recall from before: $g(x)\ge 1$ for one class, $g(x)\le -1$ for the other. Combine both into one inequality by leveraging the label $y_i \in \{+1,-1\}$ itself.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max \frac{2}{\|w\|} \quad \text{while classifying everything correctly:} \quad y_i(w^Tx_i+b) \geq 1 \;\; \forall i
$}
\end{center}
\begin{itemize}
\item The ``$\pm 1$'' on the right side collapses to a single ``$\geq 1$'' because $y_i$ itself flips sign for the negative class, cancelling out the sign of the right-hand side.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{From a Maximization to a Minimization}
\begin{itemize}
\item We want to \emph{maximize} $\frac{2}{\|w\|}$. Making a fraction bigger means making its denominator smaller, so this is exactly the same as \emph{minimizing} $\|w\|$.
\item Working with $\|w\|$ directly involves a square root, which is awkward for optimization software. Instead we minimize $\frac{1}{2}\|w\|^2$.
\end{itemize}
\begin{block}{Intuition}
Squaring doesn't change \emph{where} the minimum is: since $\|w\|\geq 0$ always, whatever $w$
makes $\|w\|$ smallest also makes $\|w\|^2$ smallest. We square purely for mathematical
convenience, it turns a problem with a square root into a smooth ``bowl'' shape that is much
easier for a computer to descend. The $\frac{1}{2}$ is there only to cancel a $2$ that appears
later when we differentiate, it changes nothing about the answer.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Optimization Problem, Plainly}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\min_{w,b} \; \frac{1}{2}\|w\|^2 \qquad \text{subject to} \qquad y_i(w^Tx_i+b) \geq 1 \;\; \forall i
$}
\end{center}
\begin{itemize}
\item In plain words: find the smallest $w$ possible, without ever letting any point cross into the margin.
\item This shape, a smooth bowl-like objective with straight-line constraints, is called \textbf{quadratic programming}. It's a well-studied, decades-old problem class with efficient, reliable solvers: we don't need to invent a new algorithm, we can hand this exact shape to existing software.
\item Being convex (bowl-shaped, no false valleys), it also guarantees a single, unique best answer, no risk of getting stuck in the ``wrong'' minimum.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Enter Lagrange Multipliers}
\begin{itemize}
\item The problem above has one constraint \emph{per training point}: hundreds of points means hundreds of ``don't cross this line'' rules to satisfy simultaneously.
\item The standard trick for this shape of problem: attach one multiplier $\alpha_i \geq 0$ to each point's constraint. Think of $\alpha_i$ as how much ``say'' point $i$ gets in shaping the boundary.
\item This rewrites the problem entirely in terms of the $\alpha_i$'s instead of $w$ directly, this rewritten version is called the \textbf{dual} problem.
\end{itemize}
\begin{block}{Intuition}
Don't get lost in the mechanics: this step just swaps one hard-to-solve problem (find $w,b$
directly, honoring every constraint at once) for an equivalent easier one (find one number
$\alpha_i$ per training point). It turns out most $\alpha_i$ come out as exactly 0, and only
the non-zero ones (the support vectors) end up mattering, that's the whole payoff.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Dual Problem}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max_{\alpha} \; W(\alpha) = \sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, x_i^Tx_j \qquad \text{s.t.} \;\; \alpha_i\geq0,\;\; \sum_i \alpha_i y_i = 0
$}
\end{center}
\begin{itemize}
\item $\sum_i \alpha_i$: a reward for each point's ``say'' $\alpha_i$, bigger alphas score higher.
\item $\frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\,x_i^Tx_j$: a penalty for how much every \emph{pair} of points agrees or disagrees, subtracted off.
\item $\alpha_i\geq0$: no point can have negative ``say''.
\item $\sum_i \alpha_i y_i = 0$: the positive and negative classes' total ``say'' must balance out.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Recovering w and b from the Alphas}
\[
w = \sum_i \alpha_i y_i x_i
\]
\begin{itemize}
\item Once the $\alpha_i$'s are solved for, $w$ falls out directly: it's a weighted combination of the training points, weighted by how much ``say'' ($\alpha_i$) each one has.
\item $b$ is then recovered from any single support vector (any point with $\alpha_i>0$), by plugging it back into $y_i(w^Tx_i+b)=1$ and solving for $b$.
\item So the whole algorithm reduces to: solve for the $\alpha_i$'s, then read off $w$ and $b$.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Support Vectors: Why Most Points Don't Matter}
\[
\alpha_i \text{ mostly } 0 \;\Rightarrow\; \text{few } x_i \text{ matter}
\]
\begin{itemize}
\item Most of the alphas come out as exactly 0. Only the points with $\alpha_i>0$, the \textbf{support vectors}, contribute to $w$.
\item These are exactly the points sitting on (or violating) the margin boundary. Every other point, however far away, could be deleted without changing $w$ or $b$ at all.
\item So this is a machine that only needs to remember its support vectors.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Similarity Term}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\max_{\alpha} \; W(\alpha) = \sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \underbrace{x_i^Tx_j}_{\text{similarity}}
$}
\end{center}
\begin{itemize}
\item Points far away DO NOT MATTER, much like Nearest Neighbor where only local points matter, except here we don't have to pick $K$ by hand: quadratic programming tells us exactly which points (and how many) are support vectors.
\item The $x_i^Tx_j$ term is a dot product: large when the two points point in a similar direction, near zero when they're roughly perpendicular. It's a similarity measure between points.
\end{itemize}

\begin{block}{Intuition}
All that algebra, across this whole section, boils down to one idea: instead of solving
directly for the widest gap, we rephrase it as ``minimize $\|w\|$'', a smooth, convex problem
that optimization software already knows how to solve reliably. The reward for the detour is
that the solution turns out to depend on only a handful of training points (the support
vectors); every other point, however far from the boundary, could be deleted without changing
the answer at all.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: SVM Optimization}
\begin{block}{Think About It}
If you added a new training point that lies far from the decision boundary, on the correct
side of the margin, would the SVM's maximal-margin hyperplane change? What does your answer
tell you about how much of the training set actually ``matters'' to an SVM?
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: SVM Optimization}
\begin{block}{Answer}
No: the hyperplane depends only on the support vectors (the points sitting on or violating
the margin). A point that's already correctly classified with room to spare gets an alpha of
0 in the dual solution, so adding or removing it changes nothing. This is why SVMs can
generalize well from relatively few ``boundary case'' examples, most of the training data
turns out to be redundant once the support vectors are known.
\end{block}
\end{frame}

\item Generally chosen by analyst following cross-validation

\begin{frame}[fragile] \frametitle{Soft Margin: Why We Need It}
\begin{itemize}
\item Everything so far assumed a \textbf{hard margin}: a line that separates the two classes perfectly, with zero mistakes.
\item Real data is messier. One noisy or mislabeled point sitting on the wrong side can mean \emph{no} separating line exists at all, the hard-margin problem has no solution.
\item Even when a perfect line does exist, forcing zero mistakes can mean bending the boundary sharply around a single outlier, hurting how well it generalizes to new points.
\item Fix: allow a controlled number of violations, in exchange for a wider, more robust margin.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Soft Margin: The Slack Variable}
\begin{itemize}
\item Introduce one slack variable $\xi_i \geq 0$ per training point, measuring how much that point is allowed to violate the margin.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{
\begin{tabular}{c|l}
\textbf{Value of $\xi_i$} & \textbf{What it means} \\ \hline
$\xi_i = 0$ & Correctly classified, outside the margin. No penalty. \\
$0 < \xi_i \leq 1$ & Correctly classified, but inside the margin. \\
$\xi_i > 1$ & Misclassified: on the wrong side of the boundary. \\
\end{tabular}
}
\end{center}
\begin{itemize}
\item Each point's constraint relaxes from $y_i(w^Tx_i+b)\geq 1$ to $y_i(w^Tx_i+b)\geq 1-\xi_i$: the point is allowed to fall short by $\xi_i$.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Soft Margin: The Full Objective}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\min \; \frac{1}{2}\|w\|^2 + C\sum_i \xi_i \quad \text{s.t.} \;\; y_i(w^Tx_i+b) \geq 1-\xi_i, \;\; \xi_i \geq 0
$}
\end{center}
\begin{itemize}
\item Two competing goals in one objective: $\frac{1}{2}\|w\|^2$ still wants the widest possible margin, while $C\sum_i \xi_i$ penalizes every violation.
\item $C$ is the knob that balances them: a bigger $C$ makes violations more costly, pushing toward a narrower margin with fewer mistakes; a smaller $C$ tolerates more violations for a wider, more robust margin.
\item This is exactly the ``narrower vs.\ wider margin'' trade-off from the C-parameter slide before, now written as actual math.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{The Core Idea Behind Support Vector Machines}
\begin{enumerate}
\item Start with data in a relatively low dimension (here, 1-dimensional dosage).
\item Move the data into a higher dimension (here, 2-dimensional, by adding dosage$^2$).
\item Find a support vector classifier that separates the higher-dimensional data into two groups.
\end{enumerate}
That is the whole idea. The only open question left: how do we decide what higher-dimensional transformation to use?
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{Why Dosage Squared? Enter Kernel Functions}
\begin{itemize}
\item Why dosage$^2$ and not dosage$^3$, or some other transform? Choosing a transformation by hand does not scale.
\item Support vector machines use \textbf{kernel functions} to systematically search higher dimensions for a good support vector classifier, without the analyst hand-picking a formula.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Polynomial Kernel: Increasing the Degree}
\begin{itemize}
\item The polynomial kernel has one parameter, $D$, the degree.
\item $D=1$: relationships between observations are computed in the original 1 dimension (no transformation).
\item $D=2$: adds a second dimension based on dosage$^2$, exactly the picture on the previous slides.
\item $D=3$: adds a third dimension based on dosage$^3$, and so on for higher $D$.
\item As $D$ increases, more dimensions become available to separate the classes; the right value of $D$ is chosen with cross-validation.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Radial Basis Function (RBF) Kernel}
\begin{itemize}
\item The RBF kernel finds a support vector classifier in an infinite number of dimensions, so its transformation cannot be drawn.
\item Even so, on a new observation it behaves like a weighted nearest-neighbor model: the closest training points have the most influence on the classification, and far-away points have very little.
\item This is why RBF is the most commonly used default kernel: it adapts locally without anyone needing to specify a transformation at all.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick, Revisited}
\begin{itemize}
\item Notice that in every example above, we never actually needed the transformed coordinates themselves, only which side of the boundary a point falls on.
\item That is exactly the kernel trick: a kernel function computes the high-dimensional relationship between two points directly from their original coordinates, without ever performing the transformation.
\item The next few slides derive this precisely, starting from the dual optimization problem.
\end{itemize}
\end{frame}

\begin{frame}[fragile] \frametitle{What are Kernel Methods?: The Mapping Idea}

\begin{itemize}
\item The idea is to create nonlinear combinations of the original features to project them onto a higher-dimensional space via a mapping function $\phi(x)$, where the data becomes linearly separable.
\item In the diagram given below, the two-dimensional dataset (X1, X2) is projected into a new three-dimensional feature space (Z1, Z2, Z3) where the classes become separable.
\end{itemize}


\begin{center}
\includegraphics[width=0.8\linewidth]{svm42}

\end{center}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: The Problem}

\begin{itemize}
\item Look back at the dual problem from the optimization section: every single place $x_i$ and $x_j$ appear, they appear together, as a dot product $x_i^Tx_j$.
\item So if we first map every point into the higher-dimensional space with $\phi(x)$ (as on the previous slide), the dual problem would need $\phi(x_i)\cdot\phi(x_j)$ instead of $x_i^Tx_j$.
\item Problem: computing $\phi(x)$ explicitly can be expensive, or in some cases (as we'll see with the RBF kernel) $\phi(x)$ lives in an infinite-dimensional space and can't even be written down.
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \underbrace{\overrightarrow{x_{SVi}}\cdot\overrightarrow{x_{SVj}}}_{\text{dot product}}
$}
\end{center}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: The Shortcut}

\begin{itemize}
\item The trick: we never actually need $\phi(x)$ by itself, we only ever need the \emph{result} of $\phi(x_i)\cdot\phi(x_j)$.
\item So replace the dot product with another function computed directly on the original points, without ever forming $\phi$:
\end{itemize}
\begin{center}
\adjustbox{max width=\linewidth}{$\displaystyle
\sum_i \alpha_i - \frac{1}{2}\sum_{i,j}\alpha_i\alpha_j y_iy_j\, \phi(\overrightarrow{x_{SVi}})\cdot\phi(\overrightarrow{x_{SVj}})
$}
\end{center}
\begin{itemize}
\item If there is a function that can be represented as an inner product of a mapping function, all we will be required to know is that function and not the mapping function. That function is called a \textbf{Kernel Function}.
\end{itemize}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{The Kernel Trick: Why This Matters}
\begin{itemize}
\item We get the full power of working in a higher (even infinite) dimensional feature space, without ever paying the cost of actually computing coordinates in it.
\item Every dot product $x_i^Tx_j$ in every formula we've derived can simply be swapped for a kernel $K(x_i,x_j)$, and the rest of the machinery (the dual, the alphas, the support vectors) stays exactly the same.
\item This is why the kernel trick is considered one of the most elegant ideas in machine learning: a small algebraic substitution unlocks non-linear boundaries from a purely linear algorithm.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile] \frametitle{What are Kernel Functions and its different types?}

\begin{itemize}
\item The kernel function computes the dot product of the mapping function directly, without ever computing $\phi(x)$ itself:
\end{itemize}
\[
K(x_i,x_j) = \phi(x_i)\cdot\phi(x_j)
\]
\begin{itemize}
\item Kernel function reduces the complexity of finding the mapping function. It defines the inner product in the transformed space directly, in terms of the original points. Common choices:
\begin{itemize}
\item \textbf{Polynomial kernel}: bends the boundary into curves of a chosen degree, good for data with polynomial-shaped class boundaries.
\item \textbf{Gaussian kernel}: measures similarity as a smooth bell-curve that fades with distance, flexible but can overfit if not tuned.
\item \textbf{Radial basis function (RBF) kernel}: the most commonly used default, a special case of the Gaussian kernel; works well when no linear or polynomial boundary fits.
\item \textbf{Sigmoid kernel}: behaves like a single-layer neural network's activation, less commonly used in practice.
\end{itemize}
\end{itemize}

{\tiny (Ref: Machine Learning – SVM Kernel Trick Example - Ajitesh Kumar)}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Support Vector Machines: In a Nutshell}
\begin{itemize}
\item When two categories have no obvious linear boundary that separates them cleanly, support vector machines:
\begin{itemize}
\item move the data into a relatively high-dimensional space, and
\item find a support vector classifier there that can effectively classify the observations.
\end{itemize}
\item Whether the relationships in that higher-dimensional space are computed explicitly or via the kernel trick, the underlying idea is the same.
\end{itemize}
{\tiny (Ref: StatQuest with Josh Starmer - Support Vector Machines Clearly Explained)}
\end{frame}

\begin{frame}[fragile]\frametitle{Quick Check: Kernel Trick}
\begin{block}{Think About It}
The RBF kernel works in an infinite number of dimensions. Why doesn't this make SVMs with an
RBF kernel impossibly slow or impossible to compute at all?
\begin{enumerate}
\item[A.] It doesn't really use infinite dimensions; ``infinite'' is just a marketing term for
``very many''.
\item[B.] The kernel trick never computes the transformed coordinates: it only ever computes
the similarity $K(x_i,x_j)$ between pairs of points directly from their original coordinates.
\item[C.] Modern computers are fast enough to handle infinite-dimensional vectors directly.
\item[D.] It only works because the dosage example was one-dimensional to begin with.
\end{enumerate}
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Kernel Trick}
\begin{block}{Answer}
\textbf{Correct: B.} Every formula in the dual problem only ever needs the dot product
$x_i^Tx_j$ between pairs of points, never the coordinates $\phi(x_i)$ themselves. A kernel
function computes that dot product's higher-dimensional equivalent directly from the original,
low-dimensional coordinates, so the cost stays proportional to the number of points, not the
number of (possibly infinite) dimensions. This is genuinely a computational trick, not a

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Multiclass: One-Against-Rest}
\begin{itemize}
\item Assume a multi-class dataset with $K$ target classes.
\item Decompose into $K$ binary problems: for each class $y_i$, train one classifier $C_i$ where class $y_i$ is positive and every other class is negative.
\item \textbf{Training}: every instance is used to train each of the $K$ classifiers.
\item \textbf{Testing}: run the test instance through all $K$ classifiers.
\begin{itemize}
\item Each classifier casts a vote (a negative prediction is a vote for ``all other classes'').
\item The class with the most votes wins.
\end{itemize}
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Multiclass: One-Against-One}
\begin{itemize}
\item Assume a multi-class dataset with $K$ target classes.
\item Train $K(K-1)/2$ binary classifiers, many more than One-Against-Rest.
\item Each classifier distinguishes just one pair of classes $(y_i,y_j)$, ignoring every record that belongs to neither.
\item \textbf{Training}: each instance is only used to train the $K-1$ classifiers relevant to its own class.
\item \textbf{Testing}: run the test instance through every classifier, record one vote per class, and the class with the most votes wins.
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{SVM (Recap)}
\begin{itemize}
\item The \textbf{Maximal Margin Classifier} is the natural way to classify data when a separating hyperplane exists: no training errors allowed.
\item Real data is rarely that clean, so we loosen this into the \textbf{Support Vector Classifier}: tolerate some training errors via a soft margin.
\item When even a soft linear boundary is not enough, the \textbf{kernel trick} lets us build a linear boundary in a higher-dimensional space, giving a non-linear boundary back in the original space. Together, these three ideas are what people mean by ``SVM''.
\end{itemize}
\end{frame}
