\begin{frame}[fragile]\frametitle{Why not Linear Regression: Out of Range}
\begin{itemize}
\item Probability of winning is bound, from 0 to 1.
\item Scores can range from 0 to 50, say.
\item We need a model that turns a score into a value between 0 and 1.

\item Score 10 gives 0.08. Very low, so predict a loss.
\item But try scores 2 or 45. The line gives values outside 0 to 1. Bad!!!
\end{itemize}

\end{frame}

\item Then the function would look like mirrored ``Z''. It has kinks. Too specific!!, not good.
\item So, clearly linear regression is not a good model.
\item Can we find a better function?

\begin{frame}[fragile]\frametitle{Logit}
\begin{itemize}
\item $p$ being probability can be only between 0 to 1.% What about range of odds values?
\item Odds are $\frac{p}{(1-p)}$, the ratio of ``it happens'' to ``it does not''.
\item Taking log of odds, gives the ``logit'' function $logit(p) = log_e \frac{p}{(1-p)}$
\item Whats the range of logit values?
\end{itemize}

\begin{block}{Intuition}
Probability is trapped in a box from 0 to 1, but a straight line is not. The logit is the ladder out of that box: dividing by $1-p$ stretches the upper end to infinity, and taking the log stretches the lower end to minus infinity. Once we are outside the box, an ordinary linear expression can do its job.
\end{block}

\tiny{(Reference: Simple Linear Regression: Step-By-Step - Dan Wellisch)}
\end{frame}

 \begin{itemize}

\item Put p = 0.1, $logit(0.1) = \ln \frac{0.1}{(0.9)} = -2.20$
\item Put p = 0.01, $logit(0.01) = \ln \frac{0.01}{(0.99)} = -4.60$

\end{itemize}

\begin{frame}[fragile]\frametitle{Reverse}
We want something inverse \ldots
 \begin{itemize}
\item $logit(p) = log_e \frac{p}{(1-p)}, p = 0 \rightarrow 1$
\item We are interested in reverse
%\item Predicting the probability that a certain 
%sample belongs to a particular class, which is the inverse form of the logit function, which is defined as:

\item $\phi(z) = logit^{-1}(z) = \frac{1}{1+ e^{-z}}, z = -\infty \rightarrow \infty$
\item $z$ is any number. In our case its a linear combination of variables giving any number, and the logit inverse will return the probability
\item $logit^{-1}(z)$ is called as Sigmoid function
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Sigmoid: Why it Stays in [0, 1]}
$\phi(z) = logit^{-1}(z) = \frac{1}{1+ e^{-z}}$
 \begin{itemize}
\item If z goes towards infinity then $e^{-z}$ becomes very small , denominator almost 1, thus $\phi(z)$ becomes almost 1. 
\item If z goes towards minus infinity then $e^{-z}$ becomes very large , denominator almost infinity, thus $\phi(z)$ becomes almost 0. 
\item Thus, we conclude that this sigmoid function takes real number values as input and transforms them to values in 
the range [0, 1] with an intercept at  $\phi (z) = 0.5$
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Quick Check: Introduction}
\begin{block}{Think About It}
We rejected the straight line because it predicts probabilities below 0 and above 1. Why is capping those values at 0 and 1 not an acceptable repair?
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Introduction}
\begin{block}{Answer}
Capping keeps the output inside 0 to 1, but it destroys the information at the ends. Every score above the cap gets the identical answer 1.0, so the model can no longer say that a score of 45 is a surer win than a score of 35. The kinks also make the function non differentiable at two points, which blocks the gradient based training used later. The sigmoid solves both problems: it stays inside 0 to 1, it is smooth everywhere, and it keeps ranking the extremes.
\end{block}
\end{frame}

\begin{frame}[fragile]\frametitle{The Magic Function: Finding It}
 \begin{itemize}
\item Example problem: chances of getting Diabetes rise with age. We need a function taking $\beta_0 + \beta_1 age$ as input and giving a probability.
\item For a probability, the value must be positive and less than 1.
\item Which functions never output a negative value, for any input?
\item `Absolute' and `Square' qualify, but both hit exactly 0. One more is exponential.
\item $e^z$ is always strictly positive, but it can be greater than 1.
\item To make it less than 1, divide by the same term plus 1. Nice Trick!!
\end{itemize}

\begin{frame}[fragile]\frametitle{The Magic Function: Rearranging to a Linear Form}
 \begin{itemize}
\item Rearranging previous equation.
\item Lets say $z = \beta_0 + \beta_1 age$. So we have $p = \frac{e^z}{e^z + 1}$
\item Is it same as $p = \frac{1}{1 + e^{-z}}$? Can not believe? Try.
\item Arranging p terms and taking log on both sides $ln(\frac{p}{1-p}) = z = \beta_0 + \beta_1 age$
\item So even though the probability function is not linear (its exponential), the above arrangement is Linear function of age. Very similar to Linear Regression.
\end{itemize}

\begin{block}{Intuition}
Same model, two views: a curve in probability space, a straight line in log odds space. We fit the line, then convert back to a probability at the very end.
\end{block}

\begin{frame}[fragile]\frametitle{The Magic Function: Why ``Logistic Regression''?}
 \begin{itemize}
\item Plot of Probability vs age looks like a Sigmoid
\item As the age increases, the chances of getting diabetes are almost equal to 1 (Asymptotic).
\item As the age lowers, the chances of getting diabetes are almost equal to 0 (Asymptotic).
\item $logit(p) = \ln(p/(1-p)) = \beta_0 + \beta_1 x_1 +  \ldots + \beta_k x_k$
\item The $\ln(\frac{p}{1-p})$ is the logit function and thus the algorithm is called as Logistic.
\item It has Regression expression on the right, so its called Regression.
\item Thus this is Logistic Regression. Used for Classification
\end{itemize}

\begin{frame}[fragile]\frametitle{Interpreting the Coefficients}
 \begin{itemize}
\item Whats the meaning of Linear expression's coefficients?
\item In Linear Regression, it meant slope, or proportionality of increase of y wrt x.
\item Here thats not the case.
\item Every unit increase in $age$, $\ln(p/(1-p))$ increases $\beta_1$ units.
\item Say, for age as 35, $\beta_0 = -26.52$ and $\beta_1 = 0.78$, the regression comes to be $ = -26.52 + 0.78 \times 35 = 0.78$.
\item Is it Probability of having Diabetes??
\item No. Its logit value.
\item $p = \frac{e^z}{e^z + 1}$ where $z = 0.78$.
\item Result: Probability $p = 0.686$. Approx 69\% chance.
\end{itemize}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Interpreting the Coefficients: Exercise}
 \begin{itemize}
\item Exercise: Calculate for age 36.
\item Confirm: $z = 1.56$ and Probability comes to be 0.826.
\item Just a marginal increase in age, far more chances of getting disease.
\item But after certain age, say 45, the probability settles towards 1.
\end{itemize}

\begin{block}{Intuition}
Linear regression's straight line has no trouble predicting a probability of $-0.3$ or $1.8$, which is nonsense for something that must stay between 0 and 1. Logistic regression sidesteps this by first fitting a straight line in ``logit'' (log-odds) space, which is unbounded like any linear expression, and only converting to a probability at the very end via $p = e^z/(e^z+1)$: a curve that squashes any real number into $(0,1)$, never quite reaching 0 or 1.
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Interpreting the Coefficients: Adding Gender}
 \begin{itemize}
\item You can add one more variable to the regression part.
\item We add Gender. Here $woman$ is 1 for a woman and 0 for a man.
\item $z = \beta_0 + \beta_1 age + \beta_2 woman$
\item Assume that betas are calculated and the equation becomes: $z = -26.47 + 0.79 \times age -0.56 \times woman$
\item $\beta_2$ is negative, so at the same age a woman's \emph{odds} are $e^{-0.56} = 0.57$ times a man's.
\item Each coefficient multiplies the odds, it does not add to the probability.
\end{itemize}

\begin{frame}[fragile]\frametitle{Optimization \ldots}
 \begin{itemize}
\item $logit(p) = \ln(p/(1-p)) = \beta_0 + \beta_1 x_1 +  \ldots + \beta_k x_k$

\item Above, p is the probability of presence of the characteristic of interest.
\item It chooses parameters that maximize  the  likelihood  of  observing  the  sample  values  rather  than  that  minimize  the  sum  of squared errors (like in ordinary regression).
\item Unlike Linear Regression, there is no closed form formula for the $\beta$s.
\item So the fitting is iterative, using gradient descent on the Log Loss (seen later).
\end{itemize}

\end{frame}

 \begin{itemize}
 \item So, by now it is clear that the Logistic Regression is somewhat a misnomer!
\item It is a classification algorithm, not a regression one.
\item We can imagine that the Logistic Regression is done in two parts.
\item In first, using X features, some intermediate y value is predicted, like Regression.
\item This value is then passed via this Analog to Digital Converter like Sigmoid function, resulting into 0 or 1.

\begin{frame}[fragile]\frametitle{Quick Check: Logistic Regression Algorithm}
\begin{block}{Think About It}
In Linear Regression, a coefficient of 0.78 means ``y goes up by 0.78 for every unit of x''. In our diabetes model $\beta_1 = 0.78$ too. Why can we not say ``the probability of diabetes goes up by 0.78 per year of age''?
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Logistic Regression Algorithm}
\begin{block}{Answer}
Because the straight line is fitted in logit space, not in probability space. $\beta_1$ is the change in \emph{log odds} per year, so the odds get multiplied by $e^{0.78} = 2.18$ each year. The effect on the probability itself is not constant: it depends on where you already are on the curve. Our worked example moved from 0.686 to 0.826, a jump of 0.14, but the same one year step near age 60 would barely move the probability at all, because the curve has flattened out near 1.
\end{block}
\end{frame}

% \item 
% Let $P(X)$ denote the probability of an event $X$ occurring. 
% \item In that case, the odds ratio $(OR(X))$ is defined by  $\frac{P(X)}{1-P(X)}$, which is essentially the ratio of the probability of the event happening, vs. it not happening. 
% \item It is clear that probability and odds convey the exact same information. But as $P(X)$ goes from 0 to 1, $OR(X)$ goes from 0 to $\infty$.
% \item 
% However, we are still not quite there yet, since our boundary function gives a value from $–\infty to \infty$. So what we do, is take the logarithm of $OR(X)$, called the log-odds function. 
% \item Mathematically, as $OR(X)$ goes from 0 to $\infty$, $log(OR(X))$ goes from $–\infty to \infty$!

% \end{itemize}

% \item Now we can say $log(OR_+) = \textbf{w}^\text{T}\textbf x$ as both are from $–\infty to \infty$ and once we equate, we are essentially putting $y = f(x)$, thus, then, the weights could be found out during Training.
% \item Expanding $OR_+$ we get $log (\frac{P_+}{1-P_+}) = \textbf{w}^\text{T}\textbf x$
% \item Taking 'log' to other side as $e$, the equation becomes $P_+ = \frac{e^{\textbf{w}^\text{T}\textbf x}}{1+ e^{\textbf{w}^\text{T}\textbf x}} = \frac{1}{1 + e^{-\textbf{w}^\text{T}\textbf x}}$

\begin{frame}[fragile]\frametitle{Multi Class: Softmax (Multinomial)}
\begin{itemize}
\item One vs All trains the classes separately, so their probabilities need not add up to 1.
\item Softmax is the direct generalisation of the sigmoid to $K$ classes.
\item One linear expression $z_k$ per class, then $p_k = \frac{e^{z_k}}{\sum_{j=1}^{K} e^{z_j}}$
\item Same trick as before: exponential makes every term positive, dividing by the total forces the range to 0 to 1.
\item Now the $K$ probabilities do add up to 1, because each is a share of one common total.
\item For $K = 2$ this reduces exactly to the sigmoid we started with.
\item This is what \texttt{LogisticRegression} in scikit-learn fits by default for multi-class targets.
\end{itemize}
\end{frame}

\begin{frame}[fragile]\frametitle{Regression vs. Classification}
\begin{itemize}
\item In standard linear regression, the response is a continuous variable (float). It can take any value, large/small, positive/negative, integer/float, etc.
\item In logistic regression, the response is qualitative/discrete (int, enum)
\item Binary responses: Success or failure, Spam or Ham (Not Spam), etc They are bound to only categorical values such as 0,1.
\item Its like converting analog signal (values, any float number) to digital signal (0 and 1s only)
%\item How do we do that?
\item Note: Independent variables (Xs) can be of any type, continuous or discrete, in both cases.
\item Only the target (y) decides which problem it is.
\item Continuous target means Regression. Discrete target means Classification.
\end{itemize}

\end{frame}

\begin{block}{Think About It}
For the diabetes-by-age example, why does the predicted probability keep climbing toward 1 as age increases indefinitely, rather than eventually leveling off at some realistic ceiling like 0.95?
\end{block}
\end{frame}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\begin{frame}[fragile]\frametitle{Quick Check: Logistic Regression}
\begin{block}{Answer}
The logistic (sigmoid) curve is mathematically guaranteed to approach 1 as $z \to \infty$ and 0 as $z \to -\infty$, but never actually reach either. That is a property of the function shape, not something the model learns from data. It has no concept of a domain-specific ceiling like ``max realistic risk is 95\%''; it only knows the linear relationship it fit in logit space, extrapolated forever in both directions. This is exactly why extrapolating far outside the range of your training data is risky, in logistic regression just as much as linear regression.
\end{block}
\end{frame}
